React App — Section 3: MetricCard Component Design

The most complex piece. The backend returns a polymorphic card shape; React needs to render it correctly.

What the API returns (ISQFMetricCard)

The /api/sqf/summaryCards/<level>/<date>/<code> endpoint returns an array of cards. Each card has this shape (from the Angular typings):

// Core card fields
cardName: string // e.g. "sales"
cardType: "summary" | "details"
cardTitle: string
cardHeader: string
reportingPeriod: string // e.g. "WTD"
seq: number // display order
// Data fields (polymorphic)
infoNumbers?: [{val, label, color}]
chartData?: {labels[], datasets[]}
tableData?: {headers[], rows[]}
tabs?: ISQFTabData[]
// Error state
error?: {cutOffTime?, generic?, level?}
hidden?: boolean
// Behaviour
isDetailsPageAvailable: boolean
canDrillDown: boolean
childCode?: string

Card rendering variants

● Chart card
Has chartData → renders Chart.js bar/pie chart
● Table card
Has tableData only → renders a data table, no chart
● Tabbed card
Has tabs[] → tab switcher, each tab has own chart/table
● Error card
error is set → shows cut-off time or generic error message
● Hidden card
hidden: true → not applicable for this level, skip rendering

MetricCard component structure

// components/cards/MetricCard/
📄 MetricCard.tsx ← root: picks variant, handles skeleton/error
📄 MetricCardHeader.tsx ← title, sub-title, reporting period, colour bar
📄 MetricCardKpiRow.tsx ← infoNumbers (KPI values + labels)
📄 MetricCardChart.tsx ← Chart.js bar/pie via react-chartjs-2
📄 MetricCardTable.tsx ← tableData, expandable rows
📄 MetricCardTabs.tsx ← tab switcher wrapper
📄 MetricCardFooter.tsx ← "See details" link, last updated, info icon
📄 MetricCardError.tsx ← error states (cut-off, no data, generic)
📄 MetricCardSkeleton.tsx ← loading placeholder (CSS animation)
📄 index.ts ← re-export
// styles
📄 MetricCard.module.css ← scoped CSS, uses CSS vars from globals

Card colour logic (matches Angular)

Green — positive trend
Red — negative trend
Amber — mixed/warning
Grey — no trend data

Colour comes from infoNumbers[0].color in the API response. A colorVal() utility function computes it in Angular — we'll replicate this as a pure function in React.
